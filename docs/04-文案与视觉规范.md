# 文案与视觉规范 · 餐谋

> 这个产品的界面有一半是文案。用户看不懂一句话，功能就等于没做。
> 麻烦的是：文案的对错不像代码能报错，所以必须写成可检查的规则。

---

## 1. 四句话决定语气

1. **说量，不说味。** 炒菜两勺酱油吃着不咸，钠早超了。
   所以是「盐有点多」，不是「有点咸」。味觉词会把"量的问题"讲成"口味问题"。
2. **说下一步。** 只报数字不给动作 = 没说完。
   「今天 1855，超 282」后面必须跟一句「明天早饭少油、中午正常吃」。
3. **不说教。** 超支是事实，不是道德问题。不写"您已超标"，不写"注意节制"。
4. **同一结论只说一次。** 三顿都写"盐有点多"，不是提醒三次，是一句话被复读三遍。

## 2. 对照表（写之前先看这个）

| ❌ 别这么写 | ✅ 这么写 | 为什么 |
|---|---|---|
| 您已摄入 1855 大卡 | 今天 1855 | "您已摄入"是机器话，且数字用大字展示，不需要句子包装 |
| 有点咸 | 盐有点多 | 说量不说味 |
| 您已超标 282 大卡，请注意控制 | 超了 282 | 数字本身就是信息，说教只是噪音 |
| 建议增加蛋白质摄入 | 蛋白差一半 · 加个蛋或豆腐 | 给具体动作，不给指标名 |
| 今日不可再进食 | 今天就吃到这 | 收工是他自己的决定，不是系统禁令 |
| 检测到您今日运动量为…… | 今天动了多少 | 人话 |
| 碳水 | 碳水（可留），但图标不能替掉这两个字 | 名词必须写全 |
| 一份 / 1 份 | 全吃了 / 一半 / 几口 | 人在饭桌上想的是"还剩半盘" |
| 酒 白酒 2 两 | 白酒 2 两 | 品类名已含"酒"，前缀重复 |
| 下馆子 | 出去吃 | 后者谁都懂 |

**灰字说明的数量是有配额的。** 已经删掉的话不要再加回来：
「可以不填」「不方便打字就用说的」「盘子和碗一起拍进去更准」——
这些都是在承认界面没讲清楚，而不是在帮用户。

## 3. 数字

| 场景 | 规则 |
|---|---|
| 热量 | 整数，不加"大卡"后缀在数字旁（标题里写一次就够） |
| 盐 | 克，一位小数（`1.9/5g`）。**不显示毫克** |
| 体重 | 一位小数（`77.4`） |
| 估算值 | 前面加"约"（`约 145 卡`），不加"约"的地方必须是实测值 |
| 百分比 | 只在有意义的对比里出现（"前 3 样占 50%"），不为了好看算百分比 |
| 大小对比 | 用"顶得上""差不多"这类人话，不用"相当于 XX 倍" |

换算常量必须写对：**1 克盐 = 400 毫克钠**。`sodiumLimitMg / 400` 才是克数，
用 `/1000` 会显示成"盐 10.1/2g"。

---

## 4. 字数与断行

- 正文 13–15px；**15px 一行塞 12 个汉字会断成孤字**（"…豆/腐"）。要么压字数，要么降字号。
- 卡片标题 ≤8 字；副标题 ≤14 字；解释性灰字 ≤30 字，超过就换行写两句。
- 提醒行：结论 15px 加粗 + 「· 」+ 补充 13px 灰。实测 390 宽下四行不折行。
- 每个断行都要当成一次换行机会来设计，不能靠"应该放得下"。

---

## 5. 图标

| 规则 | 说明 |
|---|---|
| **只在 ≥17px 用** | 13px 下图标糊成方块，"在外 油炸"会被看成"约 0 油炸" |
| **图标是索引，不是名词** | 拿掉图标还能读懂 = 合格；拿掉就读不懂 = 必须补字 |
| 一组最多三个 | 超过三个就没人扫了 |
| 彩色图标必须 `stroke="none"` | Icon 父级 svg 默认 `stroke=currentColor 1.7`，不写会镶一圈黑边 |
| 小程序用 data URI | 微信不支持 `<svg>` 标签，用 `background-image` + `encodeURIComponent` |
| 抽象形状撑不住小尺寸 | "肉"试了十版都不行，最后用猪头（靠耳+鼻+孔三样结构，比例怎么变都认得出） |

图标是在**实际渲染尺寸**上判断的，不是在 24px 画布上看着对就行。

## 6. 颜色

| 变量 | 值 | 用在哪 |
|---|---|---|
| `brand-500` | `#1f8a5b` | 主按钮、选中态、正常值 |
| `brand-600` | `#176f49` | 深一档的文字/图标 |
| `brand-50` | `#eef8f2` | 选中背景、已收工卡片 |
| `warn-500` / `warn-600` | `#e8871e` / `#c56f10` | 提示、次要警告 |
| 超支红 | `#d94f3d` / 文字 `#b23c2c` | 超预算、录音中 |
| `ink-900/700/500/300` | `#1b2320` / `#3b4642` / `#6b7671` / `#b6bdb9` | 正文 / 次要 / 说明 / 极弱 |

- 颜色只表**状态**，不表**类别**（类别用图标形状区分）。
- 进度条三态：没超（绿）/ 快超（黄）/ 超了（红）。不为了好看加渐变。

---

## 7. 布局尺寸

- 设计基准 **390 宽**，必须兼容到 **375**（四颗盐标签在 375 下会折行，就是那时候暴露的）。
- 触控目标 ≥ 44×44；列表行内的小按钮 ≥ 28×28 并加 `shrink-0`。
- 行内固定宽度的元素（分钟数 `w-10`、卡路里 `w-12`）**必须 `shrink-0`**，
  否则窄屏下"快走"会被挤成一个字。
- 弹层 `max-w-lg` 居中，桌面上不能糊满全屏。
- 底部固定栏 + 悬浮按钮会压内容：写截图脚本时别当成布局 bug（踩过两次）。

---

## 8. 状态必须可见

用户按了按钮，界面必须给出反应，且反应要和他预期一致：

| 动作 | 界面必须变 |
|---|---|
| 收工 | 环从"还能吃 620"→"今天吃了 1855"；主按钮从绿块 16 高 → 白底 12 高「再记一顿」 |
| 撤销收工 | 面板自动收起（留在原地他会以为没生效） |
| 语音 | 空闲只留话筒图标；录音显示秒数 + 红点；转写显示转圈；出错才写字 |
| 改名重算 | 数字当场变，并给一行绿色提示"热量已按新名字重算" |
| 识别失败 | 照片留在原地 + 「再试一次」，不能只剩一句"失败了" |

**"静默成功"等于"没成功"。** 这是这个产品最容易犯的错。
