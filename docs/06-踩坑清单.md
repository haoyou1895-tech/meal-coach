# 踩坑清单 · 餐谋

> 报错或行为诡异时先在这里搜。每条都有编号，讨论时说 K07 就行。
> 新增坑的格式：**现象 → 原因 → 解法**，一句话说完。

---

## A. 环境与构建

**K01 · `npm run build` / `next build` 报 validator 相关错误**
沙盒拦构建，要删 `.next/types/validator.ts` 才能过。
→ 别本地 build。`tsc --noEmit` 过了就 push，让 Vercel 云端构建。

**K02 · puppeteer 打 `127.0.0.1:3000` 页面白屏、body 为空**
系统代理导致 HMR websocket 失败。
→ 一律用 `http://localhost:3000`。

**K03 · `evaluateOnNewDocument` 注入的数据刷新后被盖回去**
它每次导航都执行。
→ 注入前判 `if (!localStorage.getItem(KEY))`。

**K04 · 截图里柱子/内容被切掉一半**
固定底栏 + 悬浮按钮在 fullPage 截图下压住内容。
→ 截单个 section，或先 `scrollIntoView`。这个假警报踩过两次。

**K05 · puppeteer 点按钮点到了别的元素**
目标被浮层（底部悬浮按钮）遮挡。
→ `page.evaluate(el => el.click())` 直接触发 DOM 事件。

**K06 · React 受控 input 用 `page.type` 后状态不更新**
需要原生 setter + 派发 `input` 事件。
→ `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,"value").set.call(el, v)` 再 `dispatchEvent(new Event("input", {bubbles:true}))`。

**K07 · `git push` 反复 502 tunnel / Connection reset**
本地代理线路挂了（GitHub 用 IP 访问被拒）。
→ 直连：`git -c http.proxy= -c https.proxy= push origin main`。不用改 git 配置，重试也行。

**K08 · GitHub 解析到假 IP（如 57.155.223.240）**
DNS 被污染。→ 隔几分钟重试直连；梯子开着时直连反而正常。

**K09 · npm 报 `Invalid Version:` 装不上任何包（mini）**
`esbuild-loader` 依赖的镜像 packument 缺版本。→ `package.json` 加 `"overrides": {"esbuild": "0.25.0"}`。

**K10 · babel-preset-taro peer 冲突**
它要 `@babel/preset-react@7`、`preset-typescript@7`、`preset-env@7`，而最新是 8.x。
→ 显式装 `@7`。

## B. 模型与接口

**K11 · 百炼所有模型返回 `AccessDenied.Unpurchased`**
Key 有效但账号无免费额度（非新用户）。→ 充值 10 元，约 2 分钟生效。
`model_not_found` 是另一回事：业务空间看不到这个模型名。

**K12 · `qwen3-asr-flash` 返回 `InternalError.Algo.InvalidParameter: ... does not support this input`**
ASR 接口**不支持 system message**。→ 去掉 system，只留 user。

**K13 · 静音录音转出「嗯。」**
→ 前端加语气词过滤，返回 422 提示"没听清"。

**K14 · 线上 `POST /api/recognize` 报 `FUNCTION_INVOCATION_TIMEOUT`**
Vercel 默认 10s。→ `maxDuration = 60`，同时放弃重试、上传图从 900px/0.82 降到 720px/0.75。

**K15 · 用 700KB 原图直测接口得到 44s 502，以为接口坏了**
真实路径是浏览器压缩后的 ~120KB，5–7 秒返回。
→ **别用极端样本下结论。** 压缩不是优化，是必需步骤。

**K16 · 改名之后拍照识别开始失败**
改名接口和拍照共用了一个限流器，改几个菜名就把当天 80 次拍照额度吃光。
→ `createLimiter()` 工厂，改名单独一套（12 次/分、150 次/天）。

**K17 · 本地 h5 预览调接口被同源策略拦**
→ 验证脚本加 `--disable-web-security` + userDataDir（Windows 用 `os.tmpdir()`，别用 `/tmp`）。
**不要为此在后端开 CORS**，那等于白送接口；真机不受同源限制。

## C. 样式与布局

**K18 · 年龄数字本该 56px，实际显示 17px；所有按钮字号都被压平**
`globals.css` 里 `input, select, textarea, button { font-size: 17px }`（防 iOS 聚焦缩放）没放进 `@layer`，
优先级压过所有 Tailwind 类。→ **这条全局规则绝不能包含 button。**

**K19 · 提醒行前面的圆点不显示（0×0）**
`<span class="h-[7px] w-[7px] rounded-full">` 是行内元素，不吃宽高。→ 加 `block`。

**K20 · 15px 一行里塞 12 个汉字，断成孤字（"…豆/腐"）**
→ 压字数，或把补充文字降到 13px。

**K21 · 13px 的小图标糊成方块，"在外 油炸"被看成"约 0 油炸"**
→ 图标只在 ≥17px 用，13px 一律只用文字。

**K22 · 彩色图标镶了一圈黑边**
`Icon` 父级 svg 默认 `stroke=currentColor strokeWidth=1.7`。
→ 彩色图标每个形状写 `stroke="none"`。

**K23 · 375 窄屏下「快走」被挤成一个字**
行内固定宽度元素（`w-10` 分钟数、`w-12` 卡数）没有 `shrink-0`。
→ 加上；同时 w-11→w-10、w-14→w-12。

**K24 · 四颗盐标签在 375 下必然折行**
`.salt-tag { flex:1; min-width:30% }` → 30%×4=120%。
→ `flex: 1 1 0; min-width: 0`。"出去吃"比"下馆子"多一个字才暴露出来。

## D. 小程序 / Taro

**K25 · 小程序 h5 预览整页全白，小程序里正常**
CSS 变量只挂在 `page` 上，浏览器没有 `page` 元素。→ `page` 和 `:root` 各挂一份。

**K26 · 小程序样式在浏览器里整条失效**
用了 `rpx`，浏览器视为非法单位，整条规则被丢。→ 统一 px / `tw()`。

**K27 · h5 里 `process is not defined`**
`process.env.TARO_APP_API_BASE` 在 h5 炸，在小程序里静默 undefined。
→ 接口地址写死 + 注释说明改哪行。

**K28 · h5 里 `compressImage` 报 temporarilyNotSupport**
→ `image.ts` 分平台：h5 走 canvas 兜底，否则预览永远用原图。

**K29 · h5 注入 localStorage 后读出空状态**
Taro h5 的 storage 格式是 `{"data": 值}`。→ 按这个结构注入。

**K30 · `Taro.env.USER_DATA_PATH` 在 h5 是 undefined**
草稿照片链路在 h5 上测不出来。→ 只能信真机，在体验版首测时确认。

**K31 · `tw()` 换算差 6%，整页错位**
网页根字号 17px，1 单位 = 4.25px，不是 4px。
→ 基准 1px=1px（designWidth 375、deviceRatio 375:2）。

**K32 · mini 的 scss 报变量不存在**
只有 `$ink-900/700/500/300`，没有 `$ink-400`。→ 用现成的档位。

**K33 · 小程序改动推上去了，用户看不到变化**
`dist` 没重建，或用户没从小程序「最近使用」里划掉（冷启动才拉新包）。

## E. 数据与计算

**K34 · 升级后昨天的运动计划消失**
`ExercisePlan` 结构从单项改成 `items[]`，没写归一化。
→ `normalizePlan()` 两种格式都读，并在 `loadState()` 和备份恢复里都调用。

**K35 · 编辑面板保存后照片全丢了**
照片是异步从 IndexedDB 读的，没读完就保存 → 被当成"被删了"。
→ 加 `photosReady` 闸门。

**K36 · 体重显示的是一周前的数**
代码假设 `weights[0]` 是最新，导入或顺序变化就错，且数字看着完全正常。
→ `latestWeightKg()` 自己取日期最大那条。

**K37 · 盐显示"10.1/2g"**
`plan.sodiumLimitMg` 是**钠毫克**，克数 = `/400`（1g 盐=400mg 钠），不是 `/1000`。

**K38 · 显示「酒 白酒 2 两」**
`drinksLabel()` 返回值已含品类（"白酒 2 两"），前面不要再加"酒 "。

**K39 · 补拍第二张后，那杯酒凭空消失**
`upsertMeal` 合并时 drinks / tags 被旧的顶掉了。
→ 合并而不是覆盖。

**K40 · 作息时间被一次夜宵带歪**
用平均数算。→ 用中位数；每餐至少要 2 条记录才认。

**K41 · 14:00 补记早饭，提示"早饭太晚，明天提前半小时"**
拿"现在的钟点"当基准。→ 改成固定合理窗口（早 7–9 / 午 11:30–13 / 晚 17:30–19:30），给区间不给相对量。

**K42 · 识别失败但界面显示了一组漂亮数字**
早期会塞演示数据"已填入估算值"。→ 删除。宁可报错，不给假数据（H4）。

**K43 · 补账写着"明天起 3 天"，实际只存了 1 天**
循环里逐天调 `onPlanItems(date, items)`，每次回调拿到的都是**同一份旧 state**，
后一次把前一次覆盖掉，最后只剩最后一天。界面不报错，只是悄悄骗人。
→ 一次交上去：`onPlanMany([{date, items}, ...])`，在 `page.tsx` 里链式累加完再落盘。
凡是"一口气改多处"的写操作，都要检查这个。

**K44 · `new Date("2026-11-24")` 在负时区退回前一天**
这个写法按 UTC 解析，`getDate()` 出来是本地时间，东八区没事、西半球会错一天。
→ 拆字符串再 `new Date(y, m-1, d)`，和 `shiftDate()` 一致。

**K45 · 输入框打第一个字符就被改成最小值**
`onChange` 里直接 clamp，他打"1"立刻被改成 5，第二个字符永远打不进去。
→ 打字过程中只存草稿，失焦或回车才收敛（`Stepper.tsx`）。

**K46 · 图标越画越不像，最后画成一个方块**
24px 下画乒乓球和羽毛球的区别，是给自己出难题。
→ 按"动作方式"分配图标，同方式共用（ADR-017）。图标是索引，名词靠文字。

**K47 · 补账"每项先给 15 分钟"，把高效项的时间吃掉了**
选三项时，3×15=45 分钟起步就占了当天上限 75 的大半，剩下的只够给第一项加，
结果"快走 + 散步 + 瑜伽"补了 261 卡，比只做快走 75 分钟（322 卡）还少。
**用户选得越多、补得越慢**，这和直觉反着来，他只会觉得系统坏了。
→ 起步降到 10 分钟，剩下的按 kcal/min 从高到低分。10 分钟是"做了"的最小单位。

**K48 · 单项上限 1.5 倍太保守，逼着所有账都摊成两天**
`sessionCap = defaultMin × 1.5` 之下，游泳最多 45 分钟、快走 60 分钟，
444 大卡任何组合都补不完。而"三天"是最容易断的周期。
→ 改成 ×2，卡在 15–90 分钟。游泳 60、快走 80、跳绳 20、爬楼 30，都是正常人做得完的量。

**K49 · 差 23 卡也要"明天再来一趟"**
补到 421/444，剩下 23 卡就是快走 5 分钟，算法却单开一天给他排 15 分钟。
用户看到的不是"精准"，是"这软件在耍我"。
→ `fillOneDay` 末尾加一条：差额 ≤ 效率最高那项 5 分钟的消耗，就多给 5 分钟收尾。

**K50 · 一次写多天，存储顺序是反的**
`withPlanItems` 用 prepend，补账按 明天→后天→大后天 的顺序写，
存储里变成 大后天→后天→明天。界面没错（界面按 `debt.days` 顺序渲染），
但备份码导出去、或者哪天按存储顺序渲染，就是倒的。
→ 写完之后按 `date` 排序。

**K51 · 一行的名字被输入框挤没了**
运动记录行原来是 `图标 + 名字 + Stepper + 卡路里 + 垃圾桶` 一行排开。
公里要占掉输入框小一半（`5.5 公里`），再留一个卡路里列，
名字只剩四个字宽 —— 375 宽下"快走"变成"快…"。
→ 卡路里挪到名字下面那行小字，和折算结果并排放（`59 分 · 250 卡`），
名字独占一行。**先保证名字站得住，再谈数字**。

**K52 · 公里填不进去：`Stepper` 只认整数**
`Stepper` 的输入框是 `replace(/[^\d]/g, "")`，打"5.5"会被清成"55"。
体重那个 Stepper 早就调了 `step=0.1`，但只有 ± 能用，打字一直是坏的 —— 没人发现，
因为没人会在手机上敲"78.1"。
→ 加 `decimal` 开关：允许**一个**小数点，失焦时收敛到一位。
公里和体重用它，分钟和个数不用（没人说"跳了 1523.4 个"）。

**K53 · 拿网球当羽毛球，被用户打回两次**
Tabler v3.24.0 的球类只有 `ball-tennis` / `ball-basketball` / `ball-volleyball` 等，
**没有羽毛球，也没有 shuttlecock**。上一版用 `ball-tennis` 顶上，用户第一次说"含义不符合"，
换库之后还是它，第二次说"羽毛球图标还是不对"。
→ 不该硬凑。按 Tabler 的 24 网格和 2px 线宽手绘一个球头 + 羽毛裙，
并且在 `docs/04` 5.1 登记为**唯一例外**。判断标准：**名字对不上就不是近似，是错**。

**K54 · 缺两样只报了一样，他补完还是算不出来**
数据不足时，`statusText` 原来按状态优先级只输出一句（先报体重）。
可 14 天里饮食只记了 3 天、体重也只称了 3 次时，他照着"再称 3 次体重"去称，
称够了回来还是"算不出来" —— 一次就会让他觉得这功能是坏的。
→ 把两个缺口都算出来、一起说："再记 7 天三餐、再称 3 次体重"。
**凡是有多个前置条件的提示，必须把全部缺口列出来，不能按优先级只报一个。**
