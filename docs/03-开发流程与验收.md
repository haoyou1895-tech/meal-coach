# 开发流程与验收 · 餐谋

> 改完不算完，**能证明它是对的**才算完。
> 这份文档解决的是"我觉得应该没问题"和"它确实没问题"之间的差。

---

## 1. 七步流程

```
① 对齐   读 docs/CONTEXT.md + AGENTS.md（只读这两份，别通读 docs）
② 改 lib 先想数据迁移；能放 lib 的不要放组件
③ 改 UI  先看 04 的文案与尺寸规范
④ tsc    web 一次，改到 mini 再跑一次
⑤ 验证   写/跑脚本，只验改的那条路径
⑥ 上线    push → Vercel → 用 BASE_URL 跑同一脚本
⑦ 记版本  ← 不在这一轮，等他验收之后（见下）
```

### 第 ⑦ 步为什么不在这一轮

**代码每次都要推**，因为他不推上去就没法试 —— 这是他说的原话。但**版本号不是提交计数**（H23）。

```
改完 → 推线上 → 他试
        ├─ 说「这个可以」 → 这时才往 versions.json 加一条
        └─ 说「不行」     → 改动并进下一版，不留痕，不占号
```

三条推论：

- **一天最多一个版本**。同一天第二件事如果是修补，并进当天那条，不新开号。
- **一句话讲不出来，就不是一个版本**。"修好 20 周却叫快一点"是 v0.12 的补丁，它本身不配一号。
- **历史那 15 条不回炉**。改了会破坏 commit 校验，而且密集的前段对作品集不是缺点 —— 能看出节奏在收敛。

```
node tools/changelog.mjs --check   # 加之前：只校验（commit 在不在、号连不连）
node tools/changelog.mjs           # 加之后：校验 + 重新生成表格和 changelog.html
```

第 ① 步不能跳。跳过它的典型后果：花两小时做了一个"运动抵扣当天额度"的漂亮功能，
然后被告知这个方向从第一天就被否了（D2）。但"对齐"不等于"通读" —— 有疑问才去查对应的那一份。

## 2. 验证矩阵

| 改了什么 | 必须验什么 | 怎么验 |
|---|---|---|
| 纯文案 | 文案在页面上、不折行、不溢出 | 截图（375 + 390 两个宽度） |
| 布局/样式 | 375 和 390 下都不挤 | 截图，量 `getBoundingClientRect` |
| 计算逻辑（预算/热量/盐/运动） | 数字能对上、边界不炸 | 单元式脚本直接调 `lib`，或注入 state 看界面 |
| 数据字段/结构 | **老数据还能读** | 注入上一版格式的 state，看界面是否正常 |
| 识别/语音接口 | 真实返回、失败有兜底 | 拦截接口塞固定数据（不花 token）+ 真调一次 |
| 小程序改动 | weapp 编译过、`dist` 比源码新 | `npm run build` + `find src -newer dist/app.js` |
| 上线后 | 线上真的有新代码 | 见 6.1 的"线上存在性检查" |

## 3. 验证脚本怎么写

模板在 `web/scripts/verify-exercise-input.mjs`，照抄结构即可。四条硬要求：

### 3.1 注入状态，别走引导流程

引导有 8 步，走一遍就 30 秒。直接塞 `localStorage`：

```js
await page.evaluateOnNewDocument((profile) => {
  if (!localStorage.getItem("mealcoach.v1")) {
    localStorage.setItem("mealcoach.v1", JSON.stringify({
      profile, meals: [], weights: [], activities: [], exercises: [],
      closedDays: [], exercisePlans: [], onboarded: true,
    }));
  }
}, PROFILE);
```

**`if (!...)` 这个判断不能少**：`evaluateOnNewDocument` 每次导航都执行，
刷新页面时会把你刚点出来的数据盖回初始值，然后你会以为是功能坏了。

### 3.2 用 localhost，不是 127.0.0.1

Next 16 dev 下 `127.0.0.1` 会因系统代理导致 HMR websocket 失败、页面白屏。
脚本一律 `http://localhost:3000`。

### 3.3 拦截花钱的接口

识别一次要钱、要时间。验证 UI 时用 `page.setRequestInterception` 塞固定 JSON，
只在最后跑一次真调用确认链路通。

### 3.4 支持线上跑

`const BASE = process.env.BASE_URL || "http://localhost:3000"`。
上线后用同一条命令打线上，才算验完。

跨域（mini h5 预览打 canmou.net.cn）要加 `--disable-web-security` + userDataDir；
**真机不受影响，别为此去开服务端 CORS**。

## 4. 上线

### 4.1 网页版

```bash
git -c http.proxy= -c https.proxy= push origin main
```

- 代理开着的机器上要用 `-c http.proxy=` 强制直连；Clash 混合端口是 `7897`
- push 失败很常见（Connection reset / 502 tunnel / DNS 假 IP），**重试或直连**，别改 git 配置
- Vercel 部署约 20–60 秒

**线上存在性检查**（页面是客户端渲染，HTML 里搜不到文字）：

```bash
curl -s https://canmou.net.cn/ | grep -o '/_next/static/immutable/chunks/[^"]*\.js'
# 下载这些 chunk，grep 你这次新写的文案
```

### 4.2 小程序

```bash
cd mini && npm run build      # 出 dist/
# 微信开发者工具打开 mini/ → 上传 → 后台「选为体验版」→ 让用户划掉小程序重进
```

`dist` 不重建就等于没改。提交代码时如果没重建，**必须在汇报里写明**。

### 4.3 回滚

- 网页：`git revert <sha>` → push → Vercel 自动重构建
- 小程序：后台「版本管理」可回退到上一个线上版本，不用重新审
- 数据库：没有数据库，最坏情况是用户清缓存 —— 所以改结构前必须留归一化

## 5. 汇报模板

默认**三行**。他要的是"哪儿变了、坏了怎么退、下一步做什么"，其余他不读：

```markdown
**改了什么**：一句话说清行为变化 + 外观有没有变（变了说清哪里）
**回滚**：git revert <sha>
**下一步**：只给一个动作
```

只有这三种情况才往下补：

| 情况 | 补什么 |
|---|---|
| 动过数据字段 | 老数据会不会读不了 |
| 有他没料到、一定会踩到的边界 | 一句话说清边界 |
| 验证方式不是默认那套（比如只验了本地） | 说清哪部分没验、为什么 |

**不要写**：原理推导、备选方案对比、"我做了以下检查"的清单、文件清单、
重复一遍他说过的话。想补充判断依据就在正文里带一句，别开小节。

"外观有变化"必须主动说 —— 用户打开页面发现不一样却没人告诉他，比功能有 bug 更伤信任。
这一条不能省，因为它只占半行。

## 6. 卡住时先查这里

| 现象 | 原因 | 解法 |
|---|---|---|
| `next build` 报 validator 相关错误 | 沙盒拦构建 | 不本地 build，tsc 过了就 push |
| 页面白屏、body 空 | 用了 `127.0.0.1`，HMR 失败 | 换 `localhost` |
| 截图有元素被挡住 | 固定底栏/悬浮按钮在 fullPage 下压住内容 | 截单个 section，或先 `scrollIntoView` |
| 点按钮没反应 | 元素被浮层遮挡，puppeteer 点到了上层 | `page.evaluate(el.click())` 直接触发 |
| 输入框里 React 状态不更新 | 受控组件必须用原生 setter | `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,"value").set.call(el, v)` 后派发 `input` |
| 小程序 h5 全白 | CSS 变量只挂在 `page` 上 | `:root` 也挂一份 |
| 小程序样式在浏览器里失效 | 用了 `rpx` | 改 px / `tw()` |
| push 一直 502 | 本地代理线路挂了 | `-c http.proxy= -c https.proxy=` 直连 |

## 7. 时间和节奏

- 预计超过两分钟的操作（批量验证、装依赖、全量截图）**先报预计耗时再动手**。
- 不要用"怕你累"当理由限制批量活儿 —— 标注类体力活对用户很便宜，真正的成本是他听不懂解释。
- 一次只推**一个**下一步。给三个选项，他会去换个工具重来。
- 长任务放后台跑，别让对话卡在等待上；跑完先看日志再说话。
