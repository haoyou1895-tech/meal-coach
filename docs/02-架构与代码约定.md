# 架构与代码约定 · 餐谋

> 一个功能要改哪里、哪些文件不能碰、数据怎么改才不丢 —— 这份说了算。
> 架构原则只有一条：**产品逻辑只写一遍，平台差异各自兜住。**

## 2. 单一源与同步

`web/src/lib/` 是唯一源，`tools/sync-shared.mjs` 往 `mini/src/lib/` 单向复制。

**当前 SHARED 清单（10 个）**：`types.ts`、`nutrition.ts`、`advice.ts`、`comment.ts`、
`drinks.ts`、`mealTags.ts`、`portion.ts`、`ranking.ts`、`mock.ts`、`store.ts`。

**还没纳进去的**：`exercise.ts`、`exerciseParse.ts`。这是已知欠账 ——
搬小程序「今日收工」时必须加进清单，否则两端运动算法会分叉。

**只有三个文件各端自己写**，因为它们碰的是平台能力：

| 文件 | web | mini |
|---|---|---|
| `storage.ts` | `localStorage` | `Taro.setStorageSync` |
| `photos.ts` | IndexedDB | 文件系统 `USER_DATA_PATH` |
| `image.ts` | canvas 压缩 | `Taro.compressImage`（h5 无此 API，走 canvas 兜底） |

规则：
- 要改逻辑 → 只改 web 那份，然后 `cd mini && npm run sync`（`build`/`dev` 前会自动跑）
- 要临时验证 mini 的行为 → 改 web，跑 sync，**不要**为了快直接改 mini
- 加新的共享 lib → 记得加进 `SHARED`，并同步更新这份文档

## 3. 数据与存储

### 3.1 位置

| 存什么 | 存哪 | 键 / 库名 |
|---|---|---|
| 全部文字状态 | `localStorage` | `mealcoach.v1`（单个 JSON） |
| 照片 | IndexedDB | 库 `mealcoach-photos`，表 `photos`，键是 photoId |
| 小程序照片 | 文件系统 | `USER_DATA_PATH/photos/{id}.jpg` |

没有账号、没有云端。换机/清缓存 = 全丢，只有"搬家码"能带走文字（照片带不走，界面已注明）。

### 3.2 状态形状

`AppState`（`lib/store.ts`）：`profile`、`meals`、`weights`、`activities`（仅兼容旧数据）、
`exercises`、`closedDays`、`exercisePlans`、`onboarded`。

### 3.3 三条迁移铁律

1. **只加可选字段**，不改名、不删、不改含义。老数据读进来不能报错。
2. **结构变了要有归一化函数**，并在 `loadState()` 里调用。
   例：`ExercisePlan` 从 `{date,kind,minutes}` 改成 `{date,items[]}` 时写了 `normalizePlan()`，
   两种格式都能读；升级一次就把昨天的计划弄丢，是最贵的一种错误。
3. **备份码恢复也要走同一套归一化**，别在 `page.tsx` 里手抄字段 —— 每加一个字段就要改一次，漏了就是静默丢数据。

照片迁移是单独一条路：`migratePhotos()` 启动时把老 base64 搬进 IndexedDB。异步操作要加闸门
（`photosReady`），没读完就保存会把照片当成"被删了"。

## 4. 接口

| 路由 | 作用 | 模型 | `maxDuration` | 限流 |
|---|---|---|---|---|
| `POST /api/recognize` | 照片 + 描述 → 菜品与营养 | `qwen-vl-max`（百炼，OpenAI 兼容） | 60s | 6 次/分、80 次/天 |
| `POST /api/estimate` | 菜名 → 这一份的营养（改名重算） | 同上，纯文本 | 20s | **独立** 12 次/分、150 次/天 |
| `POST /api/transcribe` | 语音 → 文字 | `qwen3-asr-flash` | 30s | 与拍照共用 |

限流数值可由 `RATE_PER_MINUTE` / `RATE_PER_DAY` 环境变量覆盖。

要点：
- **改名限流必须独立**。共用一个限流器时，改几个菜名就把当天 80 次拍照额度吃光。
- `qwen3-asr-flash` **不支持 system message**，加了返回 `InvalidParameter`。
- 没配 `AI_API_KEY` 时返回 503，让前端走兜底，**绝不返回假数字**。
- 识别接口硬约束：一道菜 ≤2000 大卡，越界按估算值处理并标"约"。
- 后端**不为本地预览开 CORS**，那等于白送接口。小程序/真机不受同源限制。

## 5. 构建与技术约束

| 约束 | 说明 |
|---|---|
| 不在本地 build | 沙盒会拦 `next build`，要删 `.next/types/validator.ts` 才能过。tsc 过了就 push，Vercel 构建 |
| Next 16 用 turbopack | 静态产物在 `/_next/static/immutable/chunks/*.js`，验证线上是否更新要去这里搜关键词（页面是客户端渲染，HTML 里没文字） |
| Tailwind 4 | 类名直接写在 JSX；颜色用主题变量（`brand-*`/`ink-*`/`warn-*`） |
| 全局 CSS 有雷 | `globals.css` 里有一条 `input, select, textarea { font-size: 17px }` 防 iOS 聚焦缩放。**绝不能把 button 写进去** —— 会压掉所有按钮字号（曾经把 56px 的数字压成 17px） |
| 小程序 | designWidth 375、`deviceRatio 375:2`，`tw()` 换算（1 单位 = 4.25px，不是 4px，差 6% 整页错位） |
| 小程序不支持 `<svg>` | 图标用 `background-image: url("data:image/svg+xml,...")` + `encodeURIComponent` |
| 小程序 CSS 变量 | 必须 `page` 和 `:root` 各挂一份，否则 h5 预览全白 |
| 小程序不用 `rpx` | 浏览器视为非法单位，整条规则被丢弃；统一 px / `tw()` |

## 6. 代码风格

- **注释写"为什么"，不写"是什么"**。现有代码的注释密度是刻意的，新代码保持同样的密度。
- 一个文件的头注释必须回答：这个文件解决什么问题、刻意没做什么。
- `lib/` 里的函数不碰 DOM、不碰 Taro，纯输入输出 —— 这样才能两端共用、才能写脚本验证。
- 组件里不做热量/预算计算，一律从 `lib` 拿。
- 提交信息写**行为**，不写"优化""调整"。参考：
  - `feat: 运动可以说了 —— 输入框 + 语音、明天能选几种`
  - `fix: 认错的菜名能改了，热量跟着重算`
