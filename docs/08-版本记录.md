## 怎么编号

| 规则 | 说明 |
|---|---|
| 一个版本 = 一次**推到线上、用户能看见**的改动 | 在本地改完没发的不算，发出去才算 |
| 版本号 `v0.N`，只增不减 | 发出去发现错，用 `git revert` 回退，**但不回收版本号** —— 回收了别人会对不上 |
| 纯内部改动不占号 | 文档、重构、测试脚本，记在当行备注里（例：v0.3 备注"含文档规范化"） |
| 一次上线里可以有好几个 commit | 表里只写**代表 commit**，全量在 `git log` |
| 每次上线后加一行 | 一行三样东西：编号 + 日期 + commit + 一句人话 |

**一句人话怎么写**：写他看得见的变化，不写实现。"近 7 天改成一天一根柱子"，
不写"RecordView 删除 MEAL_SHADE 常量"。

## 三个数字

数字不用手算，脚本会算。看 `changelog.html` 顶部那排，或者跑一次 `node tools/changelog.mjs`。

## 为什么要记这个

不是为了好看，是为了三件具体的事：

1. **回滚的时候知道回到哪。** "上一个好用的版本"是个感觉，"v0.12"是个地址。
2. **免得把改过的东西又改回去。** 很多反复都是忘了"这条上次为什么被否掉"——
   版本表连着 `docs/05-决策记录.md` 的 ADR 编号，一查就知道。
3. **给人看进度。** 面试或给舅舅看的时候，"13 次上线、9 天"比"做了一个记账 App"具体。

## 三份东西，一个源头

| 文件 | 是什么 | 能不能手改 |
|---|---|---|
| `docs/versions.json` | **唯一数据源**。一行一个版本 | ✅ 只改这里 |
| `docs/08-版本记录.md` 的表 | 从 json 生成，给人快速查 | ❌ 会被覆盖 |
| `docs/changelog.html` | 可视化时间线，双击就能开 | ❌ 会被覆盖 |

```bash
node tools/changelog.mjs           # 校验 + 重新生成两份产物
node tools/changelog.mjs --check   # 只校验，不写文件（提交前跑）
```

## 维护

- 上线后**立刻**往 `versions.json` 加一条，然后跑一次脚本，不要攒着（攒着就会忘，忘了这张表就废了）
- 加完顺手把 `docs/07` 的"现在这一件"改成下一件
- 写不出具体变化的改动，本来就不该发 —— 脚本会拦（`detail` 少于 10 个字直接报错）

### 加一条要填什么

```json
{
  "version": "0.15",          // 上一个 +1，不许跳号、不许回收
  "date": "2026-11-25",       // 推到线上那天
  "commit": "a1b2c3d",        // 代表提交的短哈希，脚本会去 git 里核
  "kind": "feat",             // feat 新增 / fix 修正 / refactor 重构
  "milestone": false,         // 结构或主张上的节点才写 true
  "title": "运动页能按周看了",
  "detail": "为什么改、改完什么样。两句话以内。"
}
```

**脚本会拦下这几种错**：版本号跳号或重复、日期倒着走、commit 在 git 里找不到、
标题超过 24 字、detail 太短像敷衍。拦下来就别硬提交 —— 那通常说明这条改动本来就不该发。
