# 08 · 版本记录

> 这份表回答两个问题：**现在是第几版**、**每一版到底改了什么**。
> 上游是 `docs/07-路线与待办.md`（还要做什么），下游是 git（每一行都能在 `git log` 里对上）。

## 怎么编号

| 规则 | 说明 |
|---|---|
| 一个版本 = 一次**推到线上、用户能看见**的改动 | 在本地改完没发的不算，发出去才算 |
| 版本号 `v0.N`，只增不减 | 发出去发现错，用 `git revert` 回退，**但不回收版本号** —— 回收了别人会对不上 |
| 纯内部改动不占号 | 文档、重构、测试脚本，记在当行备注里（例：v0.3 备注"含文档规范化"） |
| 一次上线里可以有好几个 commit | 表里只写**代表 commit**，全量在 `git log` |
| 每次上线后加一行 | 一行三样东西：编号 + 日期 + commit + 一句人话 |

**一句人话怎么写**：写他看得见的变化，不写实现。"近 7 天改成一天一根柱子"，
不写"RecordView 删除 MEAL_SHADE 常量"。

## 为什么要记这个

不是为了好看，是为了三件具体的事：

1. **回滚的时候知道回到哪。** "上一个好用的版本"是个感觉，"v0.12"是个地址。
2. **免得把改过的东西又改回去。** 很多反复都是忘了"这条上次为什么被否掉"——
   版本表连着 `docs/05-决策记录.md` 的 ADR 编号，一查就知道。
3. **给人看进度。** 面试或给舅舅看的时候，"13 次上线、9 天"比"做了一个记账 App"具体。
