# 餐谋 · 三端结构

一个人用、三端铺开，先说清楚哪份代码是"真的"，免得改完一边另一边不动。

## 目录

```
02-餐谋/
├── web/        网页版（Next.js）—— 线上 canmou.net.cn，是主线
├── mini/       小程序版（Taro + React）—— 微信里用，正在搭
├── harmony/    APP 版（鸿蒙壳）—— 把网页版包成原生 HAP
├── app/        APP 说明和以后的新工程（现在只有一个 README）
├── tools/      同步脚本
├── _backup/    动结构之前的源码快照
└── _preview/   截图
```

## 关键约定：逻辑只写一遍

热量怎么算、建议怎么说、盐怎么判、体重取哪一次 ——
这些是产品本身，改一次必须两端一起变。所以：

- **`web/src/lib/` 是唯一的源**，小程序那边的 `mini/src/lib/` 是自动同步出来的
- 在 `mini` 目录下跑 `npm run sync`（`build` / `dev` 前会自动跑）
- **不要改 `mini/src/lib/` 里的文件**，改了下次同步就被覆盖。要改就改 web 那份

只有三个文件各端自己写，因为它们碰的是平台能力：

| 文件 | 网页版 | 小程序版 |
| --- | --- | --- |
| `storage.ts` | localStorage | `Taro.setStorageSync` |
| `photos.ts` | IndexedDB | 文件系统 `USER_DATA_PATH` |
| `image.ts` | canvas 压缩 | `Taro.compressImage` |

## 运动量怎么算的

不用「活动系数」（低 1.2 / 中 1.3 / 高 1.45）了。那套东西的问题不是不准，
是**用户没法验证**：1.3 是什么意思？他只能信或者不信。

现在是：

```
一天消耗 = 基础代谢 × 1.2（日常活动）+ Σ (MET - 1) × 体重 × 小时
```

- 系数只留 1.2，代表"人是会动的"这个默认事实
- 具体运动按 MET 精确加：快走 4.3、慢跑 7.0、游泳 6.0、太极 3.0
- **减 1** 是因为基础代谢已经把"这一小时躺着也要消耗的那份"算过了，
  不减就重复计，一天能虚高两三百大卡 —— 那会直接变成他多吃的一碗饭

运动量**不放宽当天的额度**，只影响明天的预算，而且用**过去 7 天平均**：

- 否则他晚上跑了 40 分钟，环里立刻多出 170 大卡可吃 —— 运动变成换饭的筹码
- 用单日数，明天不练了额度又掉回去，他只会觉得这软件在抽风

相关文件：`web/src/lib/exercise.ts`（运动库 + 建议生成）、
`web/src/components/DaySummary.tsx`（今天的账）。

## 小程序现在能做什么

网页版有的，小程序都有（除了 PWA 的"添加到桌面"提示 —— 那个只对浏览器有意义）。

| 功能 | 状态 |
| --- | --- |
| 开屏（每次冷启动随机一句） | ✅ |
| 首次填写（身高体重目标/疾病/口味） | ✅ |
| 今天页：预算环、三条营养素 + 盐进度条、下一顿怎么吃、今日餐次、按热量排 | ✅ |
| 记录页：体重打卡、体重折线、近 7 天柱状图、按天看吃过什么 | ✅ |
| 拍照识别：最多 4 张 → 压缩 → 一次识别 → 份量三档/删错项/改菜名（热量重算）→ 存档 | ✅ |
| 识别失败：照片留在本地，可「再试一次」用同一张重发，不用重拍 | ✅ |
| 语音输入（RecorderManager → `/api/transcribe`） | ✅ |
| 酒水录入、盐标签（有汤/腌菜/出去吃/油炸） | ✅ |
| 改记录：改菜名份量（几口/一半/全吃了）、换餐次、删/补照片并重算 | ✅ |
| 设置：预算代谢体重、重新设置、搬家（备份码）、清空 | ✅ |
| 今日收工：一天的账、记运动（MET 换算）、明天的运动建议 | ❌ 只在网页版 |

⚠️ 「今日收工」还没搬到小程序。小程序的预算暂时只算日常活动（运动那项按 0），
不是 bug —— 是那块面板还没做，所以没有数据可算。

平台差异只有三处，都是形状问题不是功能问题：

1. 网页版的弹层（记一餐、设置、改记录）在小程序里是整页 —— 整页才有原生返回键
2. 语音：`MediaRecorder` 换成 `RecorderManager`，后端同一个接口
3. 图标：内联 SVG 换成 data URI 背景图（小程序没有 `<svg>`）

## 命令

```bash
# 网页版
cd web && npm run dev

# 小程序版：编译到 dist/，然后用微信开发者工具打开 mini/ 目录
cd mini && npm run dev      # 改了自动重编
cd mini && npm run build    # 出一次包
```

## 小程序上线要走的七步

1. `mp.weixin.qq.com` 注册（个人主体，身份证 + 扫脸），拿到 AppID
2. 类目选 **工具 → 效率**，不要选医疗健康
3. 装微信开发者工具，导入 `mini/` 目录，把 AppID 填进 `project.config.json`
4. `npm run build` 出 `dist/`
5. 后台配 **request 合法域名**：`https://canmou.net.cn`
6. 用户隐私保护指引里声明 **相机 + 相册**
7. 上传 → 提交审核 → 发布（这一步不影响体验版，可以长期不做）

## 发体验版：你现在只需要点这三下

前五步已经做完了（AppID 是 `wx9f2592245448b5f4`，包也编好了）。剩下的都在网页上点，
没有一行代码要改：

**① 后台配 request 合法域名**（不做这一步，扫码进去拍照识别必失败）

`mp.weixin.qq.com` → 开发 → 开发管理 → 开发设置 → 服务器域名 → request 合法域名，加
`https://canmou.net.cn`。

⚠️ 开发者工具里那个「不校验合法域名」的勾，**真机不认**。体验版是跑在真手机上的，
必须走白名单。这是最容易漏的一步，漏了就是"能打开、一拍就报错"。

**② 后台配隐私保护指引**（不做这一步，真机调相机会直接失败）

`设置` → `服务内容声明` → `用户隐私保护指引`，勾选并用一句话说明用途：

- 摄像头：拍摄饭菜照片用于识别热量
- 相册：选择已有照片用于识别热量

**③ 上传 → 选为体验版 → 加舅舅**

开发者工具右上角「上传」，版本号填 `1.0.0`，描述随便写。
然后回后台 → `管理` → `版本管理` → 开发版本右边「选为体验版」→ 生成二维码。
再进 `管理` → `成员管理` → `体验成员`，把舅舅的微信号加进去（个人主体上限 15 人）。

他自己扫那个码就能用，**不经过审核，也不需要你发布**。

改完代码想让他看到新版：重新上传 → 后台重新点一次「选为体验版」→ 让他把小程序
从「最近使用」里划掉再进（小程序是冷启动才拉新包，不划掉会一直是旧的）。

**第一次真机测试先验这四件事**：开屏能过 → 首页三个数出来了 → 拍照能识别出菜 →
说一句话能变成文字。这四件通了，剩下的都是样式细节。
