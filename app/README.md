# APP 版

这个文件夹放 APP 相关的说明和以后的新工程。现在实际能跑的那个 APP 在 **`../harmony`** ——
一个把 `canmou.net.cn` 包成原生鸿蒙 HAP 的壳，网页代码一行没改，只换了「谁来显示它」。

**为什么不把 harmony 挪进来**：它的构建路径、DevEco 工程配置都指向现在这个位置，
搬进子目录得重新配一遍，换不来任何好处。目录好看不值这个风险。

## 现状

| 端 | 在哪 | 状态 |
| --- | --- | --- |
| 网页版 | `../web` | 线上跑着，canmou.net.cn |
| 小程序版 | `../mini` | 骨架搭好，正在填 |
| APP 版 | `../harmony`（鸿蒙壳） | 能装机，本质是浏览器 |
| 真 · 跨端 APP | 这里 | 没开始 |

## 以后真要做 APP，选哪条路

**第一条：Taro 打包成 APP（推荐）**

`../mini` 里那套页面，Taro 能同时编到 react-native。也就是说小程序写完，APP 版基本白送。
代价是原生能力（后台计步、通知栏提醒）要单独写桥接，拍照和语音这些常规能力没问题。

**第二条：只做壳，里面装网页版**

用 Capacitor / WebView 装 `canmou.net.cn`。
一天能出包，但拍照、语音、离线都会打折扣，而且跟现在网页版一模一样 —— 那还不如让人直接开浏览器。

**第三条：原生重写**

不推荐。这个产品一年内的改动量还很大，两套原生代码维护不起。

## 为什么现在不做

小程序已经能覆盖 90% 的使用场景：舅舅不用装东西，微信里就能用。
APP 真正的价值在"推送提醒"——比如"该称体重了""晚饭别喝汤"。
这件事等产品逻辑稳了再说，现在做出来也只是个空壳。

真要动手那天，从这个文件夹开始，`cp -r ../mini ./` 然后改 config。
